# Validation: DE440 Ephemeris vs JPL Horizons

## Claim
The DE440 ASCII parser produces Earth heliocentric position at J2000 epoch matching JPL Horizons to sub-meter precision.

## Reference
JPL Horizons web service, queried with:
- Target body: 399 (Earth)
- Center: 500@10 (Sun)
- Time: 2000-01-01 00:00 TDB (JD 2451544.5)
- Reference plane: ECLIPTIC
- Reference system: J2000
- Output: VECTORS, KM-S units

Reference values (from JPL Horizons):
```
X = -2.521092855899356e+07 km
Y =  1.449279195838006e+08 km
Z = -6.164165719002485e+02 km
VX = -2.983983333677879e+01 km/s
VY = -5.207633902410673e+00 km/s
VZ =  6.168441184239981e-05 km/s
```

## Method
1. Download JPL DE440 ASCII files (`header.440` + `ascp01950.440`)
2. Concatenate into single file: `cat header.440 ascp01950.440 > de440.asc`
3. Load with `JPLEphemeris::load_ascii()`
4. Query Earth at JD 2451544.5

The implementation:
- Parses DE440 ASCII header for time bounds, constants (EMRAT, AU), coefficient pointers
- Loads Chebyshev coefficient records (32-day spans)
- Evaluates via Clenshaw's algorithm
- Performs ICRF (equatorial) → ecliptic J2000 rotation by obliquity
- Decomposes Earth position from EMB minus geocentric Moon × (1/(1+EMRAT))
- Subtracts Sun's barycentric position to get heliocentric

## Error
- Position error: ~5e-6 km per axis (5 millimeters!)
- Velocity error: ~1e-11 km/s (10 picometers/s)
- Total 3D position error rounded to 0.000 km

## Notes
- This validation took multiple iterations to converge:
  - First implementation had wrong velocity scaling (Clenshaw derivative term)
  - Required correct identification of frame (ICRF) vs storage (barycentric)
  - EMB → Earth decomposition is essential (DE files store EMB, not Earth directly)
- The position error of 5 mm is at the limit of double-precision arithmetic for distances of 1.5×10⁸ km. We are essentially at machine precision.

## Limitations
- **One epoch only**: J2000 (JD 2451544.5)
- **One body only**: Earth (does not validate Mars, Jupiter, etc.)
- **No long-baseline test**: does not check that errors stay small at JD = 2287184 (1550 AD) or JD = 2688976 (2650 AD)
- The DE440 file itself is JPL's authoritative output; we are only validating that our parser correctly reads and evaluates it
- Original DE440 generation accuracy vs reality involves additional considerations (general relativity, asteroid perturbations, etc.) that are beyond the scope of this parser

## Future validation needed
- Cross-check Mars, Venus, Jupiter at multiple epochs
- Verify behavior at file boundaries (record transitions)
- Test outside the 1950-2050 range using a wider data file
- Compare velocity computed by Chebyshev derivative vs finite-difference of position
