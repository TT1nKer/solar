# Solar Relativity Phase 0B Metric Design

## Scope

Phase 0B adds the first fixed-background spacetime implementations required by
the approved v3 contract:

- a stable `Metric` interface;
- Minkowski Cartesian;
- Schwarzschild in Boyer–Lindquist/spherical coordinates;
- Kerr in Boyer–Lindquist coordinates;
- analytic Boyer–Lindquist first derivatives;
- a real `solar relativity metric` CLI path;
- independent inverse, limit, derivative, and invalid-domain validation.

It does not add Hamiltonian evolution, ray/orbit integration, horizon crossing,
Kerr–Schild coordinates, observers, rendering, or a Solar strong-field adapter.

## Dependency direction

The new metric types are L1 building blocks over the Phase 0A L0 types:

```text
cli/relativity_metric.cpp (L3)
  -> Metric implementations (L1)
  -> math/types/Dual4 (L0)
  -> standard library and existing Solar constants
```

No legacy Newtonian type depends on relativity. The CLI adapter parses external
strings into checked internal values before constructing a metric.

## Public contracts

`Metric` follows the v3 interface exactly:

```cpp
enum class Chart {
    MinkowskiCartesian,
    BoyerLindquist,
    KerrSchildCartesian
};

class Metric {
public:
    virtual ~Metric() = default;
    virtual Chart chart() const noexcept = 0;
    virtual std::string name() const = 0;
    virtual Mat4 covariant(const Contravariant4& x) const = 0;
    virtual Mat4 contravariant(const Contravariant4& x) const = 0;
    virtual std::array<Mat4, 4>
        contravariant_derivatives(const Contravariant4& x) const = 0;
    virtual bool valid_point(const Contravariant4& x) const noexcept = 0;
};
```

Schwarzschild and Kerr additionally expose analytic covariant derivatives.
This is a physical diagnostic needed to validate the inverse-derivative
identity and later chart implementations; it is not a test-only hook.

Constructors use geometrized mass `M > 0`. Kerr accepts dimensionless
`spin_chi` with `abs(spin_chi) < 1` and derives `a=M*spin_chi`. The default
external-domain margin is `1e-8 M`.

## Metric implementation

Minkowski returns `diag(-1,1,1,1)` for both matrix directions and zero
derivatives. Any finite coordinate tuple is valid.

Schwarzschild uses:

```text
f = 1 - 2M/r
g = diag(-f, 1/f, r^2, r^2 sin^2(theta))
```

Kerr uses the exact v3 definitions of `Sigma`, `Delta`, and `A`, including the
off-diagonal `g_tphi` component. Both covariant and inverse matrices are
implemented from their explicit equations; one is not generated by numerically
inverting the other.

Kerr covariant derivatives are the analytic v3 equations. Contravariant
derivatives for Schwarzschild and Kerr are computed using:

```text
partial_k g_inverse = -g_inverse (partial_k g) g_inverse
```

Stationarity and axisymmetry make the coordinate-0 and coordinate-3 derivative
matrices exactly zero.

## Domain and failure behavior

Constructors reject non-finite/non-positive mass and invalid Kerr spin with
`std::invalid_argument`.

Minkowski rejects only non-finite coordinates.

Boyer–Lindquist metrics require:

- every coordinate finite;
- `0 < theta < pi`;
- `abs(sin(theta)) > 1e-12`;
- `Sigma > 0`;
- radius greater than the outer horizon plus `1e-8 M`;
- `Delta` larger than a double-precision scale floor.

Schwarzschild uses outer horizon `2M`. Kerr exposes outer/inner horizon and
outer stationary-limit radii. Matrix and derivative requests at invalid
points throw `std::domain_error`; `valid_point` itself is `noexcept`.

No radius, angle, sine, or Delta value is clamped. Phase 0B deliberately does
not represent BL horizon crossing or the polar-axis limit.

## CLI

The real entry point is:

```bash
./solar relativity metric \
  --metric minkowski|schwarzschild|kerr-bl \
  --M <positive> \
  --spin <abs(value)<1> \
  --x t,r,theta,phi \
  [--json]
```

Minkowski defaults to `(0,0,0,0)`. BL metrics require `--x`. Schwarzschild and
Kerr require `--M`; Kerr additionally requires `--spin`.

JSON output contains metric name, chart, coordinates, covariant matrix,
contravariant matrix, and maximum inverse-identity error. Human output contains
the same numerical information. Unknown options, malformed numeric values,
invalid domains, unsupported metric names, and missing required values return
nonzero.

The oversized legacy `cli/main.cpp` receives only one include, one usage line,
and one dispatch branch. Parsing/output stays in the new focused CLI module.

## Independent validation

Tests derive expected values without calling the production formulas:

1. exact Minkowski diagonal, inverse, zero derivative, finite-domain checks;
2. literal Schwarzschild values at `M=1,r=10,theta=pi/2`;
3. literal Kerr values at `M=1,chi=0.9,r=10,theta=pi/2`;
4. covariance/inverse multiplication error below `5e-13`;
5. matrix symmetry and Lorentzian signature at ordinary exterior points;
6. Kerr `chi=0` component-by-component equality with Schwarzschild;
7. analytic covariant derivatives against a separate Dual4 expression;
8. contravariant derivatives against five-point finite differences with
   relative/absolute normalized error below `1e-8`;
9. outer/inner horizon and stationary-limit literal values;
10. rejection of horizon, axis, non-finite, invalid mass, and invalid spin;
11. real CLI JSON success and malformed/invalid-input nonzero exits.

The validation report records ordinary-point errors separately from rejected
BL singular domains. No geodesic claim is made from metric-only tests.
